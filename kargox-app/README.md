# KargoX — single Spring Boot app (backend + web UI)

This is the backend and web frontend merged into **one deployable unit**: the React app builds straight into `src/main/resources/static`, Spring Boot serves the API and the UI from the same port, and `mvn package` produces one runnable jar. Open this folder as a single project in IntelliJ and you're done — no second process, no CORS, no separate frontend server needed for a normal run.

(The React Native mobile app still can't join this — it's a separate native runtime that has to run on a phone/emulator, not inside the JVM. It stays a second project that talks to this same API over the network. See `../kargox-mobile`.)

## How it fits together

```
kargox-app/
├── pom.xml                         Maven build for the backend
├── src/main/java/com/kargox/...    Spring Boot app (same as the standalone backend)
├── src/main/resources/
│   ├── application*.yml
│   └── static/                     ← React build output lands here (gitignored, regenerated by `npm run build`)
└── frontend/                       The React app's source (this is what you edit)
    ├── package.json
    ├── vite.config.js              build.outDir points at ../src/main/resources/static
    └── src/...
```

Two new pieces vs. the standalone backend, both in `src/main/java/com/kargox/config/`:
- **`WebConfig.java`** — serves the built React files, and falls back to `index.html` for client-side routes (e.g. `/book`, `/track/5`) so direct loads and page refreshes work, without swallowing real `/api/**` 404s.
- **`SecurityConfig.java`** — updated so only `/api/v1/**` needs auth; everything else (the SPA's HTML/JS/CSS) is open, same as any static website.

## Running it (the normal day-to-day loop)

1. **Whenever you change frontend code**, rebuild it into the backend's resources:
   ```bash
   cd frontend
   npm install      # first time only
   npm run build
   ```
2. **Run the Spring Boot app** — in IntelliJ, click the green ▶ on `KargoXApplication.main()`, or `mvn spring-boot:run` from the root. One process, one port.
3. Open `http://localhost:8080` — that's the whole app, UI and API together.

There's no need to run `npm run dev` / a separate frontend server for normal use — that's only useful if you want hot-reload while actively editing frontend code (see below).

### Optional: hot-reload while editing the frontend

```bash
cd frontend
npm run dev     # http://localhost:5173, proxies /api/v1 and /ws to :8080
```
Keep the Spring Boot app running on `:8080` at the same time. Work at `:5173` for instant reload, then `npm run build` once you're happy, to bake the final version into the jar.

## Packaging a single deployable jar

```bash
cd frontend && npm run build && cd ..
mvn clean package
java -jar target/kargox-backend-1.0.0.jar
```
